01

三种策略同一个界面 TaskDemoView，同一个服务 LandingPageService，只换 ViewModel。

Tab 1

Cancel Previous

LandingPageViewModel · load()
  • 新请求到来：cancel() 旧 Task，立即启动新 Task
  • 取消是协作式的，旧任务可能还要跑一小会儿，与新任务短暂重叠
  • 旧任务拿到结果或错误，也不允许覆盖 state / currentTask
  • 调用方“发出即忘”，结果通过 @Observable 的 state 驱动 UI
Tab 2

Serial Latest

SerialLandingPageViewModel · load() async throws
  • 工作在后台执行（Task { @concurrent in … }），严格一个接一个
  • 取消旧请求后，等它真正结束再开始，绝不并发
  • 排队期间就被替换的请求永远不会执行
  • 调用方 await 结果；被替换时抛 CancellationError
Tab 3

Async Latest

AsyncLatestLandingPageViewModel · load() async throws
  • 像 Tab 1：取消旧请求后立即开始，不等旧请求停下
  • 像 Tab 2：调用方 await 结果，工作在后台执行
  • 只有最新的调用方拿到值，其余收到 CancellationError
  • 用 currentTask == task 判断自己是否仍是当前请求
Tab 2、3 的 load() 有返回值：TaskDemoView 像普通调用方一样 try await load(model)，在 Returned to caller 区域显示它拿到的结果。被替换的调用方什么都不显示，由最新的调用方报告结果。

03

代码里值得注意的八个点每一条都在源码注释里有对应说明，大多有单元测试覆盖。

01

取消是协作式的

Task.sleep 被取消时抛 CancellationError；URLSession.data(for:) 抛 URLError(.cancelled)；CPU 密集的解析要自己 try Task.checkCancellation()。

02

过期结果不能覆盖新状态

fetch 可能在 cancel() 之后才返回。写 state 前再检查一次取消；测试 staleResultDoesNotOverwriteNewerTask 覆盖。

03

被取消的任务也可能报别的错

比如取消后才到的超时。只要已被取消，就按“已取消”处理，不碰 currentTask，否则会清掉新任务的引用（staleErrorDoesNotClearNewerTask）。

04

Task 不会自己置空引用

完成后 currentTask 依旧指向它。只有“仍是当前任务”的那一个才把它设为 nil（见 finish(...)）。

05

@concurrent 让工作离开主线程

开启 Approachable Concurrency 后，nonisolated async 函数跑在调用者的 actor 上。LandingPageService.fetch() 和 Serial / Async Latest 的 Task 都标了 @concurrent，避免 500 KB JSON 解析卡住主线程。

06

task.value 不转发取消

调用方被取消，并不会取消它等待的非结构化 Task。Serial / Async Latest 用 withTaskCancellationHandler { … } onCancel: { task.cancel() } 手动转发。

07

actor 重入

load() 在 await 处挂起时，别的 load() 可能已经开始。回到主线程后用 guard !task.isCancelled 判断自己是否已被替换（reentrantLoadsKeepLatestState）。

08

别让 .loading 卡住

被取消的若是最新请求（没人接替），就把 state 回到 .idle。Serial 的 cancel() 保留 currentTask，好让下一次请求仍然等它停下。

04

核心代码Cancel Previous 和 Serial Latest 的 load() 骨架，红框是策略的关键差异。Async Latest 就是去掉 Serial 里的 await previous?.result。

Cancel Previous

func load() {
    currentTask?.cancel()
    let requestID = nextRequestID; nextRequestID += 1
    state = .loading(requestID: requestID)

    currentTask = Task { [weak self, fetch] in
        do {
            let result = try await fetch()
            // 旧任务可能在 cancel() 之后才拿到结果
            try Task.checkCancellation()
            self?.finish(state: .loaded(…))
        } catch {
            if Task.isCancelled || isCancellation(error) {
                self?.append("#\(requestID) cancelled")
            } else {
                self?.finish(state: .failed(…))
            }
        }
    }
}

Serial Latest

func load() async throws -> FetchResult {
    let previous = currentTask
    previous?.cancel()

    let task = Task { @concurrent [weak self, fetch] in
        _ = await previous?.result  // 等它真正结束
        try Task.checkCancellation()  // 排队时被替换
        return try await fetch()
    }
    currentTask = task

    let value = try await withTaskCancellationHandler {
        try await task.value
    } onCancel: { task.cancel() }

    // 重入：挂起期间可能已被更新的 load() 替换
    guard !task.isCancelled else { throw CancellationError() }
    state = .loaded(requestID: requestID, value)
    return value
}

项目结构

文件职责
TaskApp.swiftApp 入口，展示 ContentView。
ContentView.swiftTabView 三个 Tab，分别注入三种 ViewModel 与对应的 load 闭包。Tab 1 调用 model.load() 后返回 nil；Tab 2、3 直接 try await model.load() 返回结果。

TaskTests/TaskTests.swiftSwift Testing 单元测试，注入 stub fetch 闭包，不访问网络。

测试验证内容
