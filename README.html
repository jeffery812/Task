Task
cancel()

用一个真实网络请求，看清 Swift Task 的取消到底是怎么回事。

一个 SwiftUI 小应用，用三个 Tab 演示三种“只保留最新请求”的写法。每次请求先人为等待 2 秒，再去拉取一份约 500 KB 的 Landing Page JSON， 让你有足够时间连点 Fetch、Fetch ×5、Cancel，在实时日志里观察任务何时被取消、何时真正停下。

01

三种策略

同一个界面 TaskDemoView，同一个服务 LandingPageService，只换 ViewModel。

Tab 1

Cancel Previous

LandingPageViewModel.swift · load() -> Void
  • 新请求到来：cancel() 旧 Task，立即启动新 Task。
  • 取消是协作式的，被取消的旧任务可能还要跑一小会儿，与新任务短暂重叠。
  • 旧任务即使拿到了结果或错误，也不允许覆盖 state / currentTask。
  • 调用方“发出即忘”，结果通过 @Observable 的 state 驱动 UI。
Tab 2

Serial Latest

SerialLandingPageViewModel.swift · load() async throws -> FetchResult
  • 工作在后台线程执行（Task { @concurrent in … }），严格一个接一个。
  • 新请求取消旧请求后，等旧请求真正结束再开始，绝不并发。
  • 排队期间就被更新请求替换的请求永远不会执行。
  • 调用方直接 await 结果；被替换时抛 CancellationError，取消调用方也会取消工作。
Tab 3

Async Latest

AsyncLatestLandingPageViewModel.swift · load() async throws -> FetchResult
  • 像 Tab 1 一样：取消旧请求后立即开始，不等旧请求停下。
  • 像 Tab 2 一样：调用方 await 结果，工作在后台线程执行。
  • 只有最新的调用方拿到值，被替换的调用方抛 CancellationError。
  • 用 currentTask == task 判断自己是否仍是当前请求，决定是否回到 .idle。

03

代码里值得注意的八个点

每一条都在源码注释里有对应说明，并大多有单元测试覆盖。

i

取消是协作式的

Task.sleep 被取消时立刻抛 CancellationError；URLSession.data(for:) 抛 URLError(.cancelled)；CPU 密集的解析需要自己 try Task.checkCancellation()。

ii

过期结果不能覆盖新状态

fetch 可能在 cancel() 之后才返回。Cancel Previous 在写 state 前再检查一次取消；测试 staleResultDoesNotOverwriteNewerTask 覆盖。

iii

被取消的任务也可能报别的错

比如取消后才到的超时。只要 Task.isCancelled，就按“已取消”处理，不碰 currentTask，否则会清掉新任务的引用（staleErrorDoesNotClearNewerTask）。

iv

Task 不会自己置空引用

完成后 currentTask 依旧指向它。只有“仍是当前任务”的那一个才在 finish(...) 里把它设为 nil。

v

@concurrent 让工作离开主线程

开启 Approachable Concurrency 后，普通 nonisolated async 函数跑在调用者的 actor 上。LandingPageService.fetch() 与 Serial 的 Task 都标了 @concurrent，避免 500 KB JSON 解析卡住主线程。

vi

task.value 不转发取消

等待非结构化 Task 的结果时，调用方被取消并不会取消它。Serial 用 withTaskCancellationHandler { … } onCancel: { task.cancel() } 手动转发。

vii

actor 重入

load() 在 await 处挂起时，别的 load() 可能已经开始。回到主 actor 后用 guard !task.isCancelled 判断自己是否已被替换，reentrantLoadsKeepLatestState 验证。

viii

别让 .loading 卡住

被取消的若是最新请求（没人接替），就把 state 回到 .idle；用户 cancel() 时保留 currentTask，好让下一次请求仍然等它停下。

07

运行

  1. 用支持 iOS 26 SDK 的 Xcode 打开 Task.xcodeproj。
  2. 选择 Task scheme 和一个 iOS 26 模拟器，⌘R 运行。
  3. 在任一 Tab 中连点 Fetch 或点 Fetch ×5，对照日志观察取消顺序；点 Cancel 手动取消。
  4. ⌘U 运行测试，或使用下方命令行。
xcodebuild test \
  -project Task.xcodeproj \
  -scheme Task \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'

构建设置：IPHONEOS_DEPLOYMENT_TARGET = 26.0、SWIFT_APPROACHABLE_CONCURRENCY = YES，目标默认隔离为 MainActor。 运行时需要联网访问 sportsbff-ams.kindredext.net；单元测试不需要网络。模拟器名称请按本机实际可用的设备替换。
